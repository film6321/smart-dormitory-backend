# 07. Business Workflow

อัปเดตจากโค้ดวันที่ 13 ต.ค. 2569 ผลตรวจจริงแยกไว้ใน [รายงาน QA](../qa/system-flow-report.md)

## สมัครเข้าพัก: 4 ขั้นตอน

ก่อนเริ่ม ผู้สมัครอ่านคำชี้แจง HOUSING และกดยินยอม ระบบบันทึกหลักฐานตามบัญชี/รุ่น/เวลา server แล้วจึงโหลดฟอร์ม ไม่ใช่การยอมรับสัญญาในขั้นสุดท้าย

1. ยืนยันตัวตน: อัปโหลดบัตร → OCR → ตรวจแก้ชื่อ ที่อยู่ วันเกิด และข้อมูลนักศึกษา ไม่กรอกอีเมลซ้ำ ใช้อีเมลบัญชี
2. ข้อมูลติดต่อฉุกเฉินและความต้องการเข้าพัก
3. เลือก/สุ่มห้อง → QR/สลิป → ตรวจผลชำระ บันทึก draft และยอดชำระไว้ในฐานข้อมูล
4. ตรวจสัญญาที่ใช้ตัวตนจากขั้นแรกและเงื่อนไข Admin → ยอมรับและส่งใบสมัคร API บังคับ consent/identity เสมอและตรวจ snapshot; stale terms ตอบ 409 โดยเก็บยอดเดิม

การอ่านบัตรกับตรวจชำระเป็นคนละการยืนยัน ต้องตรวจเจ้าของข้อมูลและสถานะการชำระฝั่งเซิร์ฟเวอร์ ไม่เชื่อสถานะที่ส่งจากหน้าจอ

## แจ้งซ่อม

`PENDING → APPROVED → IN_PROGRESS → RESOLVED → CLOSED` ยกเลิกได้จากสถานะก่อน RESOLVED งาน RESOLVED ปิดได้เท่านั้น งาน CLOSED/CANCELLED ไม่แก้และไม่ลบรายงานรายรายการ โควตาสร้างสำเร็จ 3 ครั้งต่อวันตามเวลาไทยเก็บใน PostgreSQL ลบรายการแล้วโควตาไม่คืน

## ผู้มาติดต่อ

อ่านคำชี้แจงและยินยอมก่อน OCR → อ่านบัตร → ตรวจแก้ข้อมูล → กรอกเลขห้องและชื่อผู้พักที่ต้องการพบ → ส่งคำขอ REGISTERED อายุ 24 ชั่วโมง Admin ดู/ยกเลิกได้ ชื่อผู้พักที่กรอกไม่ใช่หลักฐานยืนยันว่าผูกกับ Tenant แล้ว และไม่ใช่การอนุมัติเปิดประตูอัตโนมัติ การเปิดประตูจำลองเป็นอีก flow หนึ่ง

## บิล

Admin ระบุห้อง รอบบิล และค่าใช้จ่าย → คำนวณตามผู้พัก → สร้างบิล → ผู้ชำระส่งสลิป → Payment API ตรวจธุรกรรม → บันทึกสถานะพร้อมป้องกันรายการซ้ำ การทดสอบที่ใช้ข้อมูลจำลองไม่ยืนยันการโอนเงินจริง

## ย้ายออกและลบข้อมูล

บันทึกย้ายออก → ปลดห้องและสถานะ INACTIVE → ตรวจบิล งานซ่อม ผู้มาติดต่อ และงานชำระค้าง → ลบโปรไฟล์ บิล ยอดชำระ งานซ่อม และข้อมูลที่ผูกจริง → เก็บบัญชี User → คิวลบไฟล์และใบหน้า → ตรวจสถานะ COMPLETE

นโยบายที่ผู้ใช้ยืนยัน 11 ต.ค. 2569: retention ลบ Tenant บิล ยอดชำระ และข้อมูลที่ผูกจริง โดยเก็บ User หลังลบผู้พัก รายการที่ลบจะไม่อยู่ในรายงานย้อนหลัง หากมีรายการค้างหรือบิลร่วมกับผู้พักอื่นจะปฏิเสธและ rollback; ไฟล์/ใบหน้าภายนอกมีคิวล้างถาวรและสถานะรอดำเนินการจนสำเร็จ

การล้างบัญชีครบ 1 ปีนับจาก lastLogin ที่ล็อกอินสำเร็จ หากไม่เคยล็อกอินใช้ createdAt ไม่นับ heartbeat/Socket และไม่รวม Admin โหมดอัตโนมัติต้องเปิดตั้งค่าก่อน ไม่ได้เปิดเพียงเพราะมี worker ในโค้ด


Admin ต้องตั้งค่าข้อมูลผู้ให้เช่า วันสัญญา อาคาร และอัตราบริการจริงในหน้าตั้งค่าระบบก่อนรับสมัคร; ค่าเริ่มต้นว่าง ไม่ใช้ที่อยู่/โทรศัพท์ตัวอย่างในสัญญา. เปลี่ยน settings ไม่แก้สัญญาที่ส่งแล้ว

logout ยกเลิก session ทุกเครื่องด้วย authSessionVersion และ clear cookie; heartbeat ไม่ขยาย retention. 2FA/Push ยังไม่รองรับ กล้อง/ประตู/SMS/provider จริงเป็น Out of scope รอบ QA นี้; web/API/mock-provider และการล้างไฟล์ยังอยู่ใน scope

## ความยินยอมใบหน้า (14 ต.ค. 2569)

FACE_ENROLLMENT แยกจาก HOUSING และสัญญา ต้องผ่านก่อนเปิดกล้อง/ส่งภาพ Service ตรวจหลักฐานของเจ้าของข้อมูลแม้ Admin ส่งภาพแทนได้ การถอนใช้การติดต่อผู้ดูแล ไม่รับรองอุปกรณ์ประตูหรือ provider จริง
