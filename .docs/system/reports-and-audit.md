# 4.11 การพัฒนา Dashboard รายงาน และการตรวจสอบ

## 1. แยกหน้าตามงาน

Dashboard เป็นภาพรวมงานที่ Admin ต้องตัดสินใจ รายงานใช้ดูข้อมูลเป็นช่วง/หมวด ส่วนวิเคราะห์ระบบใช้สถานะการทำงานและ observability ไม่ใส่ตัวเลขทุกชนิดในหน้าเดียว ส่วนกิจกรรมล่าสุดไม่แสดงหัวข้อประวัติแจ้งเตือนซ้ำอีกชั้น

## 2. Dashboard และกราฟ

| ส่วน | ความหมาย |
|---|---|
| ตัวเลขภาพรวม | ผู้พัก ห้องว่าง งานซ่อมและรายการค้างตามข้อมูลจริง |
| วงกลมสถานะห้อง | การกระจายห้องว่าง/รับเพิ่ม/เต็ม/ไม่พร้อมใช้งาน |
| ยอดชำระและค้างตามรอบบิล | เปรียบเทียบยอดเรียกเก็บกับสถานะชำระ |
| ภาพรวมบิลและการเงิน | ชำระแล้ว ยังไม่ชำระ/รอตรวจ มัดจำ Admin ยืนยัน และยอดรับเดือนนี้ |
| สแกนเข้า–ออกผู้พักรายวัน | จำนวนเหตุการณ์ที่บันทึกสำเร็จ ตัวกรองประวัติอยู่ในกล่องเดียว |
| กิจกรรมล่าสุด | เหตุการณ์ที่บันทึกได้ ไม่ใช่ประวัติทุกสถานะทั้งระบบ |

กราฟว่างต้องมี empty state ไม่สร้างแท่งหรือข้อมูลสมมติ วงกลม/แท่งมีรายละเอียดและหน่วยประกอบ ปรับกล่องกราฟให้เต็มพื้นที่ที่จัดไว้โดยไม่ทิ้งช่องว่างสูงจากการยืด card สั้นเท่ากับ card ยาวโดยไม่มีเหตุ

## 3. นิยามการเงิน

บิลชำระแล้วเป็นยอดจากบิลที่มีสถานะ PAID มัดจำรับนับ Payment ที่ billId null, มี housingRoomId, PAID และ housingApprovedAt ไม่ null ไม่บวกบิลและ Payment เดียวกันซ้ำ

วันที่รับเงินจริงในรายงานใช้ transferAt เมื่อมี หรือวันที่บันทึกยืนยันตามลำดับที่ service กำหนด รายการไม่มีวันที่ยังอยู่ในยอดรวมและยอดไม่ระบุวัน แต่ไม่ถูกสมมติให้เข้าเดือนปัจจุบัน ยอดรับไม่ใช่กำไรสุทธิหรือยอดมัดจำที่คืนได้

ข้อมูลการเงินของผู้พักที่ purge แล้วถูกลบจากยอดตามนโยบายปัจจุบัน ไม่ใช่บัญชีแยกประเภททางการเงินที่เก็บประวัติถาวร สัญญาที่ต้องการอ้างย้อนหลังควรจัดการตามนโยบายส่งมอบที่ผู้ดูแลกำหนดก่อนลบ

## 4. รายงานและ audit

ข้อมูลรายงานต้องอ่านจากข้อมูลที่บันทึกแล้ว ไม่ให้กราฟกลายเป็น source of truth การตรวจ audit และ access logs ช่วยอ้างเหตุการณ์แต่มี coverage เฉพาะจุดที่โค้ดบันทึก ไม่เรียกกิจกรรมล่าสุดว่า complete audit trail

| Endpoint | สิทธิ์/หน้าที่ |
|---|---|
| GET `/api/analytics/dashboard` | Admin ภาพรวม |
| GET `/api/analytics/observability` | Admin วิเคราะห์สถานะระบบ |
| GET `/api/analytics/metrics/raw` | Admin metrics |
| GET `/api/billing/report` | Admin สรุปบิล |
| GET `/api/audit-logs` | Admin อ่านรายการ audit |

## 5. ผลทดสอบ

| กรณี | ผล/หลักฐาน |
|---|---|
| User/ไม่มี session เรียก dashboard/settings/audit/report | IT/RT ปฏิเสธตามสิทธิ์ |
| รวมยอดบิลและมัดจำไม่ซ้ำ | UT analytics และ IT ตาม QA |
| มัดจำยังไม่ Admin ยืนยัน | ไม่เข้า approved deposit totals ตาม source/tests |
| วันที่ไม่มี/ข้อมูลว่าง | ไม่สร้างรายรับรายเดือนสมมติ |
| purged bills | RT แถวที่ผูกผู้พักหาย; ไม่นับยอดจากแถวที่ไม่มีแล้ว |
| Dashboard ทุกกราฟกับข้อมูลจริงปริมาณมาก | ยังไม่มี benchmark/ภาพรายกรณีครบ |

ตัวเลขย้อนหลังใน QA เก่าอาจเป็นข้อมูล fixture หรือ flow เดิม ต้องเลือกหลักฐานของรุ่นล่าสุดเมื่อใส่เล่ม ความสัมพันธ์ระหว่างภาพหน้าจอกับฐานข้อมูลควรระบุวันที่ capture

## 6. รูปและแหล่งอ้างอิง
