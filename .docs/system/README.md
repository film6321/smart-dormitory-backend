ฉบับอ้างอิงระบบและ regression ล่าสุด ณ **14 ตุลาคม 2569** ผล flow จริงและ load ที่อ้างอิงก่อนหน้ายังคงวันที่ทดสอบเดิม เนื้อหาบทที่ 1–5 และรายละเอียดบทที่ 4 ตามโมดูลอยู่ใน `.docs/system/` ทั้งหมด เริ่มอ่านจากไฟล์นี้และนำโฟลเดอร์เดียวไปใช้เรียบเรียงเล่มได้

## 3. ภาพรวมและขอบเขต

เทคโนโลยีหลักแยกเป็นภาษา, Runtime, Framework, UI library, เครื่องมือ build, ฐานข้อมูล, ORM, Cache และเครื่องมือติดตั้งใน [ตารางเทคโนโลยีที่ใช้จริง](deployment-and-data.md#เทคโนโลยีหลัก-แยกตามประเภท) เก็บเฉพาะส่วนหลัก ไม่แยกไฟล์สำหรับแต่ละเครื่องมือหรือ dependency รายละเอียดการสมัคร/สัญญาและย้ายออก/ล้างข้อมูลยังอยู่ใน `users-and-tenants.md` ตามสารบัญ เพื่อลดจำนวนไฟล์และเนื้อหาซ้ำ

ระบบ MEEDEE Dormitory ใช้ TypeScript, React และ Express จัดโครงสร้างงานตามโมดูลที่ทำงานร่วมกันเป็นระบบเดียว PostgreSQL 16 เป็นข้อมูลหลัก Redis เป็น cache/lock/rate limit และ presence ชั่วคราว รูปเอกสารเก็บในไฟล์และอ้างอิงจากฐานข้อมูล จึงต้องสำรองและตรวจการลบทั้งสองส่วน

ผู้ใช้งานหลักคือ Admin, User ที่มี role STUDENT และผู้มาติดต่อสาธารณะ User กับ Tenant แยกกัน: มีบัญชีได้โดยยังไม่มีโปรไฟล์เข้าพัก และลบ Tenant ได้โดยเก็บ User ไว้

**In scope:** เว็บและ flow, HTTP/สิทธิ์/validation, PostgreSQL, ไฟล์ที่ระบบเป็นเจ้าของ, draft/credit, idempotency, cleanup และการทดสอบการเชื่อมต่อด้วย mock

**Out of scope ของรอบ QA:** กล้องจริง ประตู/Edge จริง SMS จริง และ provider OCR/Face/payment/notification จริง การคง wrapper และการที่ผู้ใช้รายงาน OCR/การชำระใช้งานได้ ไม่ใช่การรับรอง provider ทั้งระบบ

## 4. วิธีอ่านหลักฐาน

| รหัส | ประเภท | สิ่งที่ยืนยันได้ |
|---|---|---|
| SR | Source review | พฤติกรรมที่อ่านจากโค้ด ยังไม่ใช่ผลทดลอง |
| UT | Unit/mock | ตรรกะและขอบเขตการเชื่อมต่อในกรณีทดสอบ |
| IT | HTTP/DB integration | Express และ PostgreSQL แยกทดสอบ; provider ใช้ mock ตามกรณี |
| RT | Runtime HTTP/DB/files | ตรวจ API ฐานข้อมูล และไฟล์ของระบบ local ที่รันจริง |
| UA | User acceptance | ผู้ใช้ยืนยันการใช้งานผ่านหน้าจอ; ระบุรายละเอียดเท่าที่ได้รับ |
| OS | Out of scope | ยังไม่รับรองการทำงานจริงในรอบนี้ |

แถวผลทดสอบในแต่ละโมดูลเป็นสรุปหลักฐาน ไม่ใช่ผลรันใหม่ทุกครั้งที่สร้างเอกสาร จำนวน tests ไม่ใช่เปอร์เซ็นต์ coverage หรือหลักฐานว่าทุก endpoint ผ่าน end-to-end

## 6. การนำไปใช้ในเล่ม

นำเนื้อหาบทหลักไปจัดตามรูปแบบสถานศึกษา และนำไฟล์โมดูลไปเป็นหัวข้อย่อยบทที่ 4 คงรหัสหลักฐานในตารางผลจนกว่าจะจัดรูปเล่มเสร็จ ภาพที่ระบุไว้ยังเป็นรายการที่ต้องจับจากระบบจริง ไม่ใช่ภาพที่สร้างหรือแนบแล้ว

ยังต้องเติมชื่อผู้จัดทำ สถานศึกษา อาจารย์ที่ปรึกษา บรรณานุกรมตามรูปแบบหลักสูตร และภาพหน้าจอที่ปกปิดข้อมูลส่วนตัว ไม่อ้างผลความพึงพอใจ accuracy หรือความพร้อม production ที่ยังไม่ได้วัด เอกสารตัวอย่างสัญญาใน QA ไม่ใช่สัญญาจริงและไม่ใช้แทนค่าตั้งค่า Admin

## 7. การนำโฟลเดอร์ไปใช้

ใช้ `.docs/system/` เป็นชุดเนื้อหาหลัก มีบทที่ 1–5 และรายละเอียดโมดูลครบในโฟลเดอร์นี้ ผลทดสอบสรุปอยู่ในเนื้อหาแล้ว ลิงก์ไป `.docs/qa/`, `tests/` และ source code เป็นหลักฐานเพิ่มเติมใน repository หากนำโฟลเดอร์ออกไปอย่างเดียว ลิงก์หลักฐานเหล่านั้นจะเปิดไม่ได้ แต่ลิงก์บทและโมดูลภายในยังใช้งานได้ หากต้องส่งหลักฐานดิบประกอบให้แนบแยกตามที่สถานศึกษากำหนด

## 8. การยินยอมข้อมูลส่วนบุคคลล่าสุด
