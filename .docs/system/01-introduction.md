# บทที่ 1 บทนำ

โครงงานเรื่อง **การพัฒนาระบบต้นแบบบริหารจัดการหอพักผ่านเว็บแอปพลิเคชัน** จัดทำขึ้นเพื่อพัฒนาระบบที่ช่วยจัดการกระบวนการสำคัญของหอพักและเชื่อมโยงข้อมูลที่เกี่ยวข้องไว้ในระบบเดียว บทนี้กล่าวถึงที่มาและความสำคัญของปัญหา วัตถุประสงค์ ขอบเขต ประโยชน์ เครื่องมือและเทคโนโลยี นิยามศัพท์ และแผนการดำเนินงาน

## 1.1 ความเป็นมาและความสำคัญของปัญหา

การบริหารจัดการหอพักเกี่ยวข้องกับข้อมูลหลายด้านที่เชื่อมโยงกัน เช่น ข้อมูลผู้ใช้งานและผู้พักอาศัย ห้องพักและสัญญา การชำระเงิน งานแจ้งซ่อม และผู้มาติดต่อ หากข้อมูลหรือขั้นตอนเหล่านี้ถูกจัดการแยกจากกัน ผู้ดูแลอาจต้องค้นหาหรือบันทึกข้อมูลซ้ำ และติดตามสถานะของแต่ละรายการได้ยาก โดยเฉพาะเมื่อรายการหนึ่งส่งผลต่ออีกส่วน เช่น การอนุมัติผู้พักต้องสอดคล้องกับสถานะห้องและข้อมูลสัญญา หรือการย้ายออกต้องพิจารณาข้อมูลที่ยังผูกอยู่กับผู้พัก

กระบวนการสมัครเข้าพักและการจัดการเอกสารยังต้องคำนึงถึงความถูกต้องและการคุ้มครองข้อมูลส่วนบุคคล ขณะที่งานประจำ เช่น การตรวจสอบการชำระเงิน การติดตามงานซ่อม และการจัดการคำขอเข้าพบ ต้องมีสถานะและประวัติที่ผู้เกี่ยวข้องตรวจสอบได้ โครงงานนี้จึงพัฒนาระบบต้นแบบบริหารจัดการหอพักผ่านเว็บแอปพลิเคชัน เพื่อรวมข้อมูลและขั้นตอนหลักไว้ในระบบเดียว กำหนดสิทธิ์ตามบทบาท และแสดงสถานะการดำเนินงานให้สอดคล้องกัน

ระบบมีส่วนเชื่อมต่อบริการ OCR และ Face Verification ผ่าน API โดยไม่ได้พัฒนาเครื่องมือประมวลผลดังกล่าวขึ้นใหม่ ส่วนการสั่งเปิดประตูในหน้าจอเป็นการจำลองการทำงาน ไม่ได้เชื่อมต่อกับอุปกรณ์ควบคุมประตูจริง โครงงานจึงมุ่งพัฒนาระบบเว็บและตรวจสอบกระบวนการที่อยู่ในขอบเขต พร้อมระบุข้อจำกัดของบริการและอุปกรณ์ภายนอกไว้อย่างชัดเจน

## 1.2 วัตถุประสงค์ของโครงงาน

1. เพื่อพัฒนาระบบต้นแบบผ่านเว็บแอปพลิเคชันสำหรับจัดการข้อมูลหอพักและกระบวนการของผู้พัก
2. เพื่อเชื่อมโยงการจัดการห้องพัก ผู้พักอาศัย สัญญา บิล งานแจ้งซ่อม และผู้มาติดต่อ พร้อมควบคุมสิทธิ์และสถานะของข้อมูล
3. เพื่อรองรับการเชื่อมต่อบริการ OCR และ Face Verification ผ่าน API ตามโครงสร้างของระบบ
4. เพื่อจัดทำหน้าจอและกระบวนการใช้งานสำหรับผู้ดูแล ผู้พัก และผู้มาติดต่อ ให้สามารถส่งคำขอและติดตามสถานะตามสิทธิ์ของตน
5. เพื่อทดสอบการทำงานของส่วนสำคัญด้วยชุดทดสอบอัตโนมัติ การทดสอบการเชื่อมต่อ และการตรวจสอบระบบตามขอบเขตที่กำหนด

## 1.3 ขอบเขตของโครงงาน

### 1.3.1 ขอบเขตด้านความสามารถของระบบ

ระบบแบ่งผู้ใช้งานหลักเป็น 3 กลุ่ม ความสามารถของแต่ละกลุ่มสรุปไว้ใน **ตารางที่ 1.1**

**ตารางที่ 1.1 ขอบเขตความสามารถของระบบจำแนกตามกลุ่มผู้ใช้**

| กลุ่มผู้ใช้ | ความสามารถของระบบ |
|---|---|
| ผู้ดูแลระบบ (Admin) | จัดการห้องและข้อมูลผู้พัก ตรวจสอบใบสมัครและสัญญา จัดการบิลและหลักฐานการชำระเงิน ติดตามงานซ่อม จัดการคำขอผู้มาติดต่อ ตั้งค่าระบบ และดูข้อมูลรายงานตามสิทธิ์ |
| ผู้พัก (Student/User) | สมัครเข้าพักและจัดการข้อมูลของตนเอง ตรวจสอบห้องและสัญญา ดูบิลและสถานะการชำระ ส่งคำขอแจ้งซ่อม และติดตามผลตามสิทธิ์ของบัญชี |
| ผู้มาติดต่อ (Visitor) | ให้ข้อมูลและส่งคำขอเข้าพบผ่านหน้าสำหรับผู้มาติดต่อ จากนั้นรอผู้ดูแลตรวจสอบและจัดการสถานะคำขอ |

ความสามารถในตารางเป็นขอบเขตตามบทบาทของระบบ ไม่ได้หมายความว่าผู้มาติดต่อสามารถควบคุมประตูจริง หรือผู้พักสามารถเปลี่ยนสถานะที่สงวนไว้สำหรับผู้ดูแลได้

### 1.3.2 ขอบเขตด้านเทคนิคและการเชื่อมต่อ

1. พัฒนาเป็นเว็บแอปพลิเคชัน ใช้งานผ่านเว็บเบราว์เซอร์ โดยส่วนติดต่อผู้ใช้และบริการเว็บทำงานร่วมกันเป็นระบบ
2. ใช้ PostgreSQL เป็นฐานข้อมูลหลัก และจัดเก็บเอกสารหรือไฟล์ที่ระบบจัดการตามการอ้างอิงในฐานข้อมูล
3. เชื่อมต่อบริการ OCR และ Face Verification ผ่าน API ตามโครงสร้างที่กำหนด การทดสอบบางกรณีใช้บริการจำลองหรือ fixture
4. การชำระเงินในขอบเขตนี้จัดการ QR หลักฐาน และสถานะตรวจสอบ ไม่ใช่การเชื่อมต่อธนาคารหรือ Payment Gateway เพื่อยืนยันและคืนเงินจริงโดยอัตโนมัติ
5. การสั่งเปิดประตูจากหน้าจอเป็นการจำลอง ไม่ถือเป็นหลักฐานการเปิดประตูหรือการทำงานของอุปกรณ์จริง

### 1.3.3 ข้อจำกัดของโครงงาน

1. ไม่ครอบคลุมการเชื่อมต่อกล้องวงจรปิด อุปกรณ์ Edge หรือชุดควบคุมประตูจริง
2. ยังไม่รับรองการทำงานของผู้ให้บริการ OCR, Face Verification, Payment หรือ Notification ภายนอกในสภาพแวดล้อม production
3. ไม่ครอบคลุมการส่ง SMS จริง และการทดสอบประสิทธิภาพต่อเนื่องระยะยาวในสภาพแวดล้อม production
4. ยังไม่มีผลการประเมินความพึงพอใจจากกลุ่มผู้ใช้จริงหรือผลการศึกษาทางสถิติที่ใช้สรุปประสิทธิผลของระบบ
5. ผลการทดสอบยืนยันเฉพาะกรณีและสภาพแวดล้อมที่ระบุในรายงาน ไม่ใช่การรับรองทุกสถานการณ์หรือทุกบริการภายนอก

## 1.4 ประโยชน์ที่คาดว่าจะได้รับ

1. ได้ระบบต้นแบบที่รวมข้อมูลและกระบวนการหลักของหอพักไว้ในเว็บแอปพลิเคชันเดียว
2. ช่วยให้ผู้ดูแลตรวจสอบสถานะห้อง ผู้พัก บิล งานซ่อม และคำขอผู้มาติดต่อจากข้อมูลที่สัมพันธ์กันได้
3. ช่วยให้ผู้พักและผู้มาติดต่อส่งคำขอและติดตามสถานะตามบทบาทและสิทธิ์ที่กำหนด
4. ได้แนวทางจัดการข้อมูลและสถานะที่สามารถใช้ตรวจสอบและพัฒนาต่อยอดได้

ประโยชน์ข้างต้นเป็นผลที่คาดหวังจากขอบเขตการพัฒนา ไม่ได้ระบุเป็นการลดเวลา ค่าใช้จ่าย หรือข้อผิดพลาดในเชิงตัวเลข เนื่องจากยังไม่มีผลการวัดเปรียบเทียบดังกล่าว

## 1.5 เครื่องมือและเทคโนโลยีที่ใช้

เครื่องมือและเทคโนโลยีหลักที่ใช้พัฒนาระบบสรุปไว้ใน **ตารางที่ 1.2** รายละเอียดเพิ่มเติมแสดงในบทที่ 2

**ตารางที่ 1.2 เครื่องมือและเทคโนโลยีหลักที่ใช้ในโครงงาน**

| ประเภท | เครื่องมือหรือเทคโนโลยี | หน้าที่ในโครงงาน |
|---|---|---|
| ภาษาโปรแกรม | TypeScript | พัฒนาส่วนติดต่อผู้ใช้และบริการเว็บ พร้อมตรวจสอบชนิดข้อมูลระหว่างพัฒนา |
| UI library | React | สร้างหน้าจอสำหรับผู้ดูแล ผู้พัก และผู้มาติดต่อ |
| Runtime และ Web framework | Node.js และ Express.js | รันบริการเว็บและจัดการ HTTP API |
| เครื่องมือพัฒนาและ build | Vite | รันและ build ส่วนเว็บระหว่างพัฒนา |
| ฐานข้อมูลและ ORM | PostgreSQL และ Prisma | จัดเก็บข้อมูลหลักและจัดการคำสั่งฐานข้อมูล |
| Cache และเครื่องมือปฏิบัติการ | Redis | รองรับ cache, rate limit และ lock ชั่วคราวในจุดที่ระบบกำหนด |
| เครื่องมือจัดสภาพแวดล้อม | Docker และ Docker Compose | สร้างและเรียกใช้บริการต่าง ๆ ในสภาพแวดล้อมของโครงงาน |

## 1.6 นิยามศัพท์เฉพาะ

คำศัพท์ที่ใช้ในโครงงานและความหมายตามขอบเขตระบบแสดงไว้ใน **ตารางที่ 1.3**

**ตารางที่ 1.3 นิยามศัพท์เฉพาะ**

| คำศัพท์ | ความหมายในโครงงาน |
|---|---|
| ระบบต้นแบบบริหารจัดการหอพัก | เว็บแอปพลิเคชันที่พัฒนาขึ้นเพื่อจัดการข้อมูลและกระบวนการหอพักตามขอบเขตของโครงงาน คำว่า “ต้นแบบ” หมายถึงระบบที่พัฒนาและทดสอบในขอบเขตนี้ ไม่ได้อ้างว่าเป็นระบบแรกหรือระบบเดียว |
| ผู้พัก (Student/User) | ผู้มีบัญชีผู้ใช้สำหรับสมัครเข้าพักและใช้บริการที่เกี่ยวข้องกับข้อมูลของตนเองในระบบ |
| ข้อมูลผู้พัก (Tenant) | ข้อมูลการเข้าพักที่เชื่อมโยงกับบัญชีผู้ใช้ ห้อง และสัญญา โดยเป็นข้อมูลคนละส่วนกับบัญชีผู้ใช้ |
| ผู้มาติดต่อ (Visitor) | บุคคลที่ส่งคำขอเข้าพบผ่านระบบ และมีสถานะคำขอหรือการเข้าพบแยกจากข้อมูลผู้พัก |
| OCR (Optical Character Recognition) | เทคโนโลยีหรือบริการสำหรับอ่านข้อความจากภาพ ซึ่งผลที่อ่านได้ต้องผ่านการตรวจสอบและแก้ไขตามกระบวนการของระบบ |
| Face Verification | การเปรียบเทียบใบหน้าผ่านบริการที่เชื่อมต่อด้วย API ผลคะแนนความคล้ายไม่ใช่ค่าความแม่นยำของระบบ |
| บริการจำลอง (Mock) | ส่วนทดแทนบริการภายนอกหรือข้อมูลจริงที่ใช้ในการทดสอบ โดยไม่ถือเป็นการทดสอบกับผู้ให้บริการจริง |

## 1.7 แผนการดำเนินงาน

จากประวัติ Git ของ Backend และ Frontend ระหว่างวันที่ 27 พฤษภาคม–14 ตุลาคม พ.ศ. 2569 พบ commit รวม 124 รายการ (Backend 49 และ Frontend 75) โดยแบ่งขั้นตอนดำเนินงานเป็น 6 ระยะตาม **ตารางที่ 1.4** ซึ่งช่วงเวลาของแต่ละระยะอ้างอิงจากแผนงานหรือบันทึกการทำงานจริง

**ตารางที่ 1.4 ขั้นตอนและระยะเวลาการดำเนินงาน**

| ระยะ | ขั้นตอนการดำเนินงาน | ผลที่ได้ | ช่วงเวลาที่ดำเนินการจริง |
|---|---|---|---|
| 1 | ศึกษาปัญหาและรวบรวมความต้องการ | ขอบเขตและความต้องการของระบบ | [เติมเดือน/ปีจริง] |
| 2 | วิเคราะห์และออกแบบระบบ | แบบจำลองข้อมูล กระบวนการ และหน้าจอ | [เติมเดือน/ปีจริง] |
| 3 | พัฒนาระบบตามโมดูล | เว็บแอปพลิเคชันและบริการที่อยู่ในขอบเขต | [เติมเดือน/ปีจริง] |
| 4 | ตรวจสอบและปรับปรุงระบบ | ระบบที่แก้ไขตามผลตรวจและข้อผิดพลาดที่พบ | [เติมเดือน/ปีจริง] |
| 5 | ทดสอบและสรุปผล | ผลทดสอบพร้อมระบุกรณีจำลองและข้อจำกัด | [เติมเดือน/ปีจริง] |
| 6 | จัดทำเอกสารและเตรียมนำเสนอ | รายงานและเอกสารประกอบโครงงาน | [เติมเดือน/ปีจริง] |

ผลการดำเนินงานตามแผนทำให้ได้ระบบต้นแบบบริหารจัดการหอพักผ่านเว็บแอปพลิเคชัน ครอบคลุมการสมัครและจัดการผู้พัก ห้องพักและสัญญา บิล งานแจ้งซ่อม ผู้มาติดต่อ และรายงาน โดยชุดทดสอบกฎธุรกิจและ API ผ่าน 185 จาก 185 กรณี ชุดทดสอบตรรกะและสถานะหน้าจอผ่าน 119 จาก 119 กรณี และการทดสอบเชื่อมต่อฐานข้อมูลในกระบวนการแจ้งซ่อมผ่าน 38 จาก 38 กรณี ผลดังกล่าวจำกัดอยู่ในกรณีทดสอบที่ระบุ ยังไม่ใช่ผลประเมินกับผู้ใช้จริงหรือการยืนยันการทำงานของกล้อง ประตู และบริการภายนอกในสภาพแวดล้อมจริง
