# ภาคผนวก ข คู่มือการใช้งานระบบ MEEDEE Dormitory

## ข.1 วัตถุประสงค์และขอบเขต

คู่มือนี้อธิบายการใช้งานเว็บระบบสำหรับผู้ดูแลหอพัก (Admin) ผู้สมัครหรือผู้พัก (User ที่มีบทบาท STUDENT) และผู้มาติดต่อ ครอบคลุมการเตรียมข้อมูล การสมัครและทำสัญญา การจัดการห้องและบิล การแจ้งซ่อม การจัดการผู้มาติดต่อ และการตรวจรายงาน ใช้ชื่อเมนูตามหน้าจอที่ตรวจพบในระบบ

ขั้นตอนที่เกี่ยวกับ OCR, Face Verification, การสร้าง QR, การชำระผ่านผู้ให้บริการ, OTP/SMS, Socket และประตูจริง อาจมีบริการภายนอกหรืออุปกรณ์ที่อยู่นอกขอบเขตทดสอบ คู่มือนี้จึงไม่ถือว่าการแสดงผลสำเร็จบนเว็บเป็นหลักฐานว่าธนาคารรับเงินแล้ว มี SMS ส่งถึงแล้ว หรือประตูจริงเปิดแล้ว ให้ตรวจสถานะล่าสุดจากระบบและปฏิบัติตามคำแนะนำของผู้ดูแล

### บทบาทผู้ใช้งาน

| บทบาท | ใช้ทำอะไร |
|---|---|
| Admin | ดูแลห้องและเงื่อนไขสัญญา พิจารณาผู้สมัคร จัดการบิล/แจ้งซ่อม/ผู้มาติดต่อ และดูรายงานธุรกิจ |
| ผู้สมัคร/ผู้พัก | สมัครและติดตามผล เลือกห้อง ชำระเงิน ส่งคำขอคืนเครดิต ดูบิล แจ้งซ่อม และจัดการข้อมูลของตน |
| ผู้มาติดต่อ | กรอกคำขอเข้าพบจากหน้าสาธารณะและเก็บเลขอ้างอิงไว้แสดงแก่เจ้าหน้าที่ |

### เตรียมก่อนใช้งาน

- ใช้อุปกรณ์และเบราว์เซอร์ที่รองรับเว็บระบบ เชื่อมต่อเครือข่าย และเปิดคุกกี้ที่จำเป็นต่อ session การเข้าสู่ระบบ
- เตรียมอีเมล/รหัสผ่านของบัญชี สำหรับผู้สมัครให้เตรียมข้อมูลส่วนตัว ผู้ติดต่อฉุกเฉิน และเอกสารตามที่แบบฟอร์มร้องขอ
- Admin ตรวจการตั้งค่าหมวดสัญญาและราคาห้องก่อนเปิดรับสมัคร เพราะระบบตรวจข้อมูลสัญญาและยอดจากฝั่งเซิร์ฟเวอร์
- ใช้บัญชีทดสอบและข้อมูลสมมติเมื่อต้องฝึกหรือจับภาพประกอบ อย่าใส่ข้อมูลจริงลงเอกสารสาธิต

## ข.2 เข้าสู่ระบบและบัญชี

1. เปิดหน้าเข้าสู่ระบบ กรอกอีเมลและรหัสผ่านของบัญชี แล้วเลือกเข้าสู่ระบบ
2. เมื่อเข้าสำเร็จ ระบบแสดงหน้าและเมนูตามสิทธิ์บัญชี
3. การเข้าสู่ระบบใหม่ด้วยบัญชีเดียวกันทำให้ session เดิมหมดสิทธิ์ หากพบข้อความแจ้งการเข้าสู่ระบบจากอุปกรณ์อื่น ให้เข้าสู่ระบบอีกครั้งบนอุปกรณ์ที่ต้องการใช้
4. ออกจากระบบเมื่อใช้เครื่องสาธารณะหรือเลิกใช้งาน
5. หากลืมรหัสผ่าน ให้เปิดเมนูลืมรหัสผ่าน กรอกเบอร์โทรศัพท์สำหรับกู้คืน ทำตามขั้นตอน OTP ที่หน้าเว็บ แล้วตั้งรหัสผ่านใหม่ หากไม่ได้รับ OTP ให้ติดต่อผู้ดูแลระบบ; การทำงานของ SMS จริงขึ้นกับการตั้งค่าผู้ให้บริการของระบบที่ใช้งาน

**ภาพประกอบที่แนะนำ:** แคปหน้าเข้าสู่ระบบโดยไม่กรอกข้อมูล และภาพหน้าหลักหลังเข้าระบบด้วยบัญชีทดสอบ ปิดอีเมล เบอร์ ชื่อจริง และข้อความแจ้งเตือนส่วนบุคคลก่อนนำไปจัดเล่ม

## ข.3 คู่มือสำหรับ Admin

### ข.3.1 ตรวจความพร้อมก่อนรับสมัคร

1. เข้าสู่ระบบด้วยบัญชี Admin
2. เปิด **ตั้งค่าระบบ** และกรอกข้อมูลผู้ให้เช่า/เงื่อนไขสัญญาในหมวด CONTRACT ให้ครบตามช่องที่ระบบกำหนด 10 ช่อง ค่าเริ่มต้นอาจว่าง จึงต้องตรวจความถูกต้องก่อนให้ผู้สมัครยื่นสัญญา
3. เปิด **จัดการห้องพัก** ตรวจเลขห้อง ประเภท ความจุ สถานะ และค่าเช่าที่แสดงในระบบ
4. ตรวจจำนวนที่ว่างและราคาให้ตรงกับนโยบายหอพักก่อนเปิดให้เลือกห้อง
5. วันเริ่มสัญญาของใบสมัครใหม่ใช้วันที่ปัจจุบันในเขตเวลา Asia/Bangkok และสิ้นสุดหลัง 5 เดือนปฏิทิน ระบบปรับเป็นวันสุดท้ายของเดือนเมื่อวันเดียวกันไม่มีในเดือนปลายทาง ไม่ต้องกำหนดวันเริ่ม/สิ้นสุดเองในหน้าตั้งค่าสัญญา

**ภาพประกอบที่แนะนำ:** แคปหน้าตั้งค่า CONTRACT ที่ใช้ข้อมูลสมมติและหน้ารายการห้องที่ไม่แสดงข้อมูลผู้พัก ใต้ภาพระบุว่าเป็นหน้าตั้งค่าระบบ/รายการห้องของผู้ดูแล

### ข.3.2 พิจารณาผู้สมัคร

1. เปิดเมนู **นักศึกษา / ผู้เช่า** หรือหน้าจัดการผู้พักอาศัย
2. ตรวจรายการใบสมัครและสถานะ เลือกรายการเพื่อดูข้อมูลที่จำเป็นต่อการพิจารณา
3. ตรวจข้อมูลส่วนตัว ผู้ติดต่อฉุกเฉิน ห้อง ยอดที่ชำระ หลักฐาน และ snapshot สัญญาตามสิทธิ์ที่กำหนด
4. อนุมัติหรือปฏิเสธตามข้อมูลจริง หากปฏิเสธ ให้ระบุเหตุผลเมื่อหน้าจอมีช่องให้กรอก ผู้สมัครที่ถูกปฏิเสธสามารถกลับไปแก้ไขและยื่นใหม่ตาม flow ที่ระบบอนุญาต
5. การเห็นสถานะชำระเงินหรือสลิปไม่ได้เท่ากับอนุมัติผู้สมัคร และการอนุมัติใบสมัครไม่ได้ยืนยันว่า provider ธนาคารทำ settlement จริงนอกระบบ
6. สำหรับคำขอคืนเครดิต ให้ตรวจกล่อง **คำขอคืนเงินจากใบสมัคร** ในหน้าจัดการผู้พักอาศัย แม้ผู้สมัครยังไม่มี Tenant ก็มี draft ให้ตรวจได้ เลือกปฏิเสธพร้อมหมายเหตุ หรือบันทึกการคืนเงินจริงหลังโอนเงินจริงแล้ว โดยระบุจำนวน เลขอ้างอิง และหลักฐานตามหน้าจอ ระบบไม่โอนเงินให้อัตโนมัติ

**ภาพประกอบที่แนะนำ:** แคปหน้ารายการสมัครและตัวอย่างหน้าตรวจคำขอคืนเครดิตด้วยข้อมูลทดสอบ ปิดบัตรประชาชน เบอร์โทร เลขบัญชี สลิป และหลักฐานทุกชนิด

### ข.3.3 จัดการบิลและการชำระเงิน

1. เปิดเมนู **บิล** เพื่อตรวจรายการบิล สถานะ รอบบิล รายการค่าใช้จ่าย และหลักฐานที่เกี่ยวข้อง
2. ใช้ตัวกรอง/รายละเอียดรายการเพื่อตรวจยอดและผู้พักก่อนดำเนินการ
3. ตรวจข้อความสถานะบนหน้าจอ เช่น ยังไม่ชำระ เกินกำหนด กำลังตรวจสอบ ชำระสำเร็จ หรือไม่สำเร็จ หากระบบแจ้งว่าต้องตรวจเพิ่มเติม ให้ดำเนินการตามคำแนะนำของผู้ดูแล
4. อย่าบันทึกผลชำระซ้ำเพื่อแก้หน้าจอค้าง ให้รีเฟรชสถานะหรือตรวจรายการล่าสุดก่อน หากระบบแสดงผลขัดกับหลักฐานภายนอก ให้ตรวจเลขอ้างอิงและส่งให้ผู้รับผิดชอบ
5. การชำระผ่าน QR/ส่งสลิปในระบบไม่ใช่หลักฐานว่าธนาคารรับเงินแล้ว จนกว่าจะมีสถานะ/การยืนยันที่ระบบใช้เป็นแหล่งข้อมูล

**ภาพประกอบที่แนะนำ:** แคปหน้ารายการบิลและรายละเอียดบิลด้วยข้อมูลจำลอง ปิดชื่อผู้พัก เลขบัญชี QR สำหรับรับเงินจริง และภาพสลิป

### ข.3.4 จัดการงานแจ้งซ่อม

1. เปิด **แจ้งซ่อมบำรุง** ดูงานใหม่และรายละเอียดตามสิทธิ์ Admin
2. ตรวจประเภท รายละเอียด เวลาติดต่อ และภาพแนบก่อนรับงาน
3. เมื่อรับงานแล้ว ให้อัปเดตความคืบหน้าตามการดำเนินงานจริง และบันทึกเมื่อซ่อมเสร็จเพื่อให้ผู้พักตรวจสอบ
4. เมื่อแจ้งว่าซ่อมเสร็จแล้ว ให้ผู้พักตรวจผลและยืนยันปิดงานด้วยตนเอง ผู้ดูแลไม่ควรยืนยันแทนผู้พัก
5. หากยกเลิกงานซ่อม ผู้ดูแลควรดำเนินการตามขั้นตอนที่ระบบกำหนด งานที่ยกเลิกแล้วไม่สามารถนำกลับมาดำเนินการต่อจากรายการเดิมได้ หากยังต้องการซ่อม ให้ติดต่อผู้ดูแลเพื่อขอคำแนะนำในการดำเนินการต่อ

**ภาพประกอบที่แนะนำ:** แคปงานซ่อมทดสอบที่แสดงสถานะและรายละเอียดสมมติ โดยปิดชื่อ ห้อง ภาพที่มีบุคคล หรือข้อมูลระบุตัวตน

### ข.3.5 จัดการผู้มาติดต่อ

1. เปิดเมนู **ผู้มาติดต่อ** เพื่อตรวจคำขอที่ส่งเข้ามา
2. ตรวจข้อมูลและเลขห้อง แล้วติดต่อผู้พัก/ตรวจยืนยันตามขั้นตอนของหอพัก
3. บันทึกการอนุญาตเข้าพบผ่านหน้าจอเมื่อผ่านการตรวจ และบันทึกจบการเข้าพบเมื่อผู้มาติดต่อเสร็จธุระ
4. ระบบแสดงว่าคำขอยังรอการตรวจสอบ เมื่อเจ้าหน้าที่บันทึกอนุญาตเข้าพบจะแสดงว่าผ่านการตรวจ และเมื่อบันทึกเสร็จสิ้นจะแสดงว่าปิดขั้นตอนแล้ว สถานะเหล่านี้มาจากการบันทึกในระบบ ไม่ได้อ่านจากอุปกรณ์ประตูหรือยืนยันว่าประตูเปิดจริง
5. ชื่อผู้พักที่ผู้มาติดต่อกรอกใช้ประกอบการตรวจสอบเท่านั้น ระบบไม่ได้จับคู่ชื่อนี้กับบัญชีผู้พักโดยอัตโนมัติ เจ้าหน้าที่จึงควรตรวจสอบกับผู้พักหรือข้อมูลในระบบก่อนบันทึกอนุญาตเข้าพบ

**ภาพประกอบที่แนะนำ:** ใช้คำขอทดสอบและปิดข้อมูลจากบัตร ที่อยู่ เบอร์โทร ภาพใบหน้า และเลขห้องจริง

### ข.3.6 รายงานและการตรวจสอบ

1. เปิด **รายงานธุรกิจ** เพื่อดูข้อมูลรายรับ/รายจ่ายและยอดตามเกณฑ์ที่หน้าเว็บแสดง
2. เปิด **วิเคราะห์ระบบ** สำหรับสรุปข้อมูลเชิงวิเคราะห์ที่ระบบจัดเตรียมไว้
3. เปิดรายละเอียดรายการหรือบันทึกตรวจสอบเมื่อจำเป็นต้องติดตามว่าใครทำรายการใด
4. ตรวจช่วงเวลา ตัวกรอง และนิยามยอดก่อนนำตัวเลขไปใช้ในเอกสาร รายงานสะท้อนข้อมูลที่ระบบบันทึก ไม่ยืนยันรายการที่ไม่ได้เชื่อมต่อกับแหล่งภายนอกจริง

**ภาพประกอบที่แนะนำ:** แคปหน้ารายงานด้วยข้อมูลทดสอบหรือสภาพแวดล้อมที่ปกปิดข้อมูลผู้พักทั้งหมด

## ข.4 คู่มือสำหรับผู้สมัครและผู้พัก

### ข.4.1 สมัครเข้าพัก

ก่อนเริ่ม ให้สร้าง/เข้าสู่บัญชี STUDENT และเตรียมข้อมูลส่วนตัว เอกสาร ผู้ติดต่อฉุกเฉิน และข้อมูลที่แบบฟอร์มร้องขอ การสมัครแบ่งเป็น 4 ขั้น:

1. **ข้อมูลส่วนตัวและยืนยันตัวตน:** อ่านคำชี้แจงข้อมูลส่วนบุคคลและยินยอม HOUSING ก่อนเปิดแบบฟอร์มหรือส่งภาพบัตร ใช้ OCR ช่วยอ่านข้อมูลจากภาพ ตรวจและแก้ไขผล OCR ทุกช่องก่อนดำเนินการ ผล OCR อาจผิดพลาดและไม่แทนการตรวจเอกสารด้วยตนเอง
2. **ผู้ติดต่อฉุกเฉิน:** กรอกชื่อ ความสัมพันธ์ และเบอร์ติดต่อที่ได้รับอนุญาตให้ใช้
3. **เลือกห้องและชำระเงิน:** เลือกหรือสุ่มห้อง ตรวจค่าเช่า เงินประกัน ยอดรวม และเครดิตที่หน้าเว็บคำนวณจากข้อมูล server ตรวจเลขห้องและยอดก่อนขอ QR/ชำระ
4. **ตรวจสัญญาและยื่นใบสมัคร:** อ่านชื่อ ที่อยู่ เงื่อนไข และวันสัญญา ยอมรับสัญญาตามจริง แล้วส่งใบสมัคร

บันทึกใบหน้าเป็นขั้นตอนและความยินยอมแยกต่างหาก FACE_ENROLLMENT ต้องมาก่อนเปิดกล้อง/เก็บภาพ ทำตามคำแนะนำบนหน้าเว็บให้ครบ 5 ภาพและรอระบบแจ้งการบันทึกเสร็จ หากบริการขัดข้องระหว่างทาง ให้ทำตามข้อความ retry; ภาพที่บันทึกสำเร็จอาจคงอยู่เพื่อส่งส่วนที่เหลือ การตอบกลับของ Face API หรือสถานะครบ 5 ภาพไม่ได้ยืนยันความแม่นยำโดยรวม การตรวจ liveness หรือการทำงานของกล้อง/ประตูจริง

**ภาพประกอบที่แนะนำ:** ภาพฟอร์มสมัครที่ใช้ข้อมูลทดสอบ ภาพเลือกห้อง/สรุปยอดที่ไม่มี QR รับเงินจริง และภาพตรวจสัญญา ปิดชื่อ เลขบัตร ที่อยู่ วันเกิด เบอร์ และข้อมูลทางการเงิน

### ข.4.2 ชำระเงินและเครดิตใบสมัคร

1. ก่อนชำระ ตรวจห้องและยอดค่าเช่ากับเงินประกันบนหน้าสรุป
2. หลังขอ QR ระบบกันสิทธิ์ห้องไว้ 10 นาทีตามเวลาที่แสดง การหมดเวลาทำให้สิทธิ์ห้องกลับไปนับในระบบ แต่ไม่ได้ยกเลิก QR ในแอปธนาคาร
3. หากยอดชำระได้รับการยืนยันแล้วหลังหมดเวลา เงินคงเป็นเครดิตของบัญชี ไม่ได้ถูกลบหรือคืนให้อัตโนมัติ ตรวจเครดิตก่อนจ่ายซ้ำ
4. เลือกห้องใหม่ได้ตามยอด/เงื่อนไขที่ระบบแสดง หากเครดิตมากกว่ายอดห้องและเลือกยื่นต่อโดยไม่ขอคืน ส่วนเกินจะไม่คืนโดยอัตโนมัติ อ่านคำเตือนก่อนยืนยัน
5. หากต้องการเงินคืน ส่งคำขอคืนเครดิตทั้งหมดจากหน้าสมัครและกรอกข้อมูลตามแบบฟอร์ม จากนั้นรอ Admin ตรวจ การส่งคำขอไม่ใช่การคืนเงินสำเร็จ และระหว่างรออาจแก้ไข/ชำระ/ส่งใบสมัครไม่ได้
6. หากอัปโหลดสลิปค้างหรือเกิดข้อผิดพลาด อย่าอัปโหลดหรือโอนซ้ำทันที ให้ตรวจรายการชำระล่าสุดและสถานะจาก server ก่อน

**ภาพประกอบที่แนะนำ:** แคปสรุปยอด ห้องที่เลือก สถานะเครดิต และคำเตือนยอดส่วนเกินโดยใช้ข้อมูลสมมติ ไม่แนบ QR หรือสลิปจริง

### ข.4.3 ดูบิลและชำระบิล

1. เปิดหน้า **บิล** เพื่อตรวจรายการและวันครบกำหนดชำระ
2. เลือกบิลที่ต้องการ แล้วตรวจรายละเอียดค่าเช่า ค่าน้ำ ค่าไฟ และรายการอื่นที่แสดง
3. ตรวจยอดรวมให้ถูกต้องก่อนชำระ และใช้ช่องทางที่หน้าเว็บแนะนำ
4. แนบหลักฐานการชำระเมื่อระบบร้องขอ จากนั้นติดตามผลจากสถานะที่หน้าเว็บแสดง
5. หากระบบแจ้งว่ากำลังตรวจสอบหรือจำเป็นต้องตรวจเพิ่มเติม ให้รอผลและอย่าชำระหรือส่งหลักฐานของรายการเดิมซ้ำ หากสถานะไม่เปลี่ยน ให้ติดต่อผู้ดูแลพร้อมเลขอ้างอิงรายการ

**ภาพประกอบที่แนะนำ:** แคปบิลตัวอย่างและสถานะที่ปกปิดชื่อ เลขบิลที่โยงกับข้อมูลจริง QR และสลิป

### ข.4.4 ส่งและติดตามงานซ่อม

1. เปิด **แจ้งซ่อมบำรุง** เลือกประเภท อธิบายปัญหา เวลาที่สะดวกให้ติดต่อ และแนบภาพที่เกี่ยวข้อง
2. ตรวจข้อมูลและส่งหนึ่งครั้ง ระบบจำกัดจำนวนคำขอที่ส่งสำเร็จต่อวันตามกติกาที่แสดง
3. ติดตามความคืบหน้าจากรายการแจ้งซ่อมของตนเอง ตั้งแต่รอผู้ดูแลรับเรื่อง ระหว่างดำเนินการ จนถึงซ่อมเสร็จและรอการยืนยัน
4. เมื่อได้รับแจ้งว่าซ่อมเสร็จ ให้ตรวจผลและยืนยันปิดงาน หากยังไม่เรียบร้อยให้ติดต่อผู้ดูแลก่อนยืนยัน

**ภาพประกอบที่แนะนำ:** จัดภาพทดสอบเป็นภาพเดียวโดยแสดง (ก) แบบฟอร์มแจ้งซ่อม และ (ข) รายการติดตามความคืบหน้าของงาน ปิดภาพส่วนตัวและข้อมูลห้องจริง

### ข.4.5 ย้ายออกและสมัครใหม่

แจ้งผู้ดูแลเพื่อดำเนินการย้ายออกตามขั้นตอน ระบบตรวจบิลค้างและงาน/รายการที่ยังเปิดอยู่ก่อนเปลี่ยนสถานะหรือล้างข้อมูล การล้างข้อมูลผู้พักเป็นกระบวนการที่มี guard และทำงานกับข้อมูล/ไฟล์ที่เกี่ยวข้อง บัญชีผู้ใช้คงอยู่ได้เพื่อเข้าสู่ระบบหรือสมัครใหม่ เมื่อหน้าจอแสดงว่าการล้างเสร็จแล้วจึงเริ่ม flow สมัครใหม่ด้วยบัญชีเดิมตามคำแนะนำ

### ข.4.6 แจ้งเตือน

เปิดกระดิ่งแจ้งเตือนเพื่อดูรายการบิล งานซ่อม หรือสัญญาที่เกี่ยวข้องกับบัญชีตนเอง เลือกรายการเพื่อไปยังหน้าที่เกี่ยวข้อง จุดแดงหมายถึงมีรายการที่ยังไม่อ่านในเบราว์เซอร์นี้ สถานะอ่านแล้วอาจไม่ซิงก์ไปอุปกรณ์อื่น หากรายการไม่อัปเดตให้รีเฟรชหรือเปิดหน้าใหม่ การแจ้งเตือนอาศัยข้อมูลสถานะที่ระบบอ่านได้และการเชื่อมต่อปัจจุบัน จึงไม่ควรใช้แทนหลักฐานการชำระหรือการดำเนินการจริง

## ข.5 คู่มือสำหรับผู้มาติดต่อ

1. เปิดหน้าลงทะเบียนผู้มาติดต่อจากลิงก์/QR ที่หอพักจัดให้
2. อ่านคำชี้แจงและทำตามขั้นตอนสแกนเอกสารที่หน้าเว็บร้องขอ ตรวจสอบและแก้ผล OCR ก่อนส่ง หากไม่ยินยอมให้หยุดและสอบถามผู้ดูแล
3. กรอกข้อมูลที่จำเป็นให้ครบ รวมข้อมูลการติดต่อ ห้อง และชื่อผู้พักที่ต้องการพบ ตรวจสอบความถูกต้องก่อนส่ง
4. หลังส่ง เก็บเลขอ้างอิงหรือดาวน์โหลดใบยืนยัน PNG ไว้แสดงต่อเจ้าหน้าที่
5. ติดต่อ Admin เพื่อให้ตรวจคำขอและบันทึกการเข้าพบ การมีเลขอ้างอิงไม่ได้อนุญาตให้เข้าหอหรือเปิดประตูด้วยตัวเอง
6. คำขอมีอายุจำกัดตามที่ระบบกำหนด หากหมดอายุหรือข้อมูลผิด ให้ติดต่อ Admin ก่อนส่งคำขอใหม่

**ภาพประกอบที่แนะนำ:** แคปแบบฟอร์มลงทะเบียนผู้มาติดต่อและใบรับคำขอหลังส่งข้อมูลเป็นคนละภาพ ใช้ข้อมูลทดสอบเท่านั้น และปิดข้อมูลบัตร ภาพใบหน้า วันเกิด ที่อยู่ เบอร์โทร และเลขอ้างอิงที่ผูกกับรายการจริง

## ข.6 การใช้งานและแก้ปัญหาเบื้องต้น

| อาการ | สิ่งที่ควรทำ |
|---|---|
| เข้าระบบแล้วพบข้อความว่าเซสชันหมดอายุ หรือมีการเข้าสู่ระบบจากอุปกรณ์อื่น | เข้าสู่ระบบใหม่บนอุปกรณ์ที่ต้องการใช้ หากพบข้อความเดิมอีก ให้ติดต่อผู้ดูแลระบบและตรวจสอบว่ามีผู้ใช้บัญชีนี้บนอุปกรณ์อื่นหรือไม่ |
| ปุ่มถัดไปยังกดไม่ได้ | ตรวจว่ากรอกข้อมูลในช่องที่จำเป็นครบแล้ว อ่านคำแนะนำใต้ช่อง และตรวจว่ายอมรับคำชี้แจงที่กำหนดแล้วหรือไม่ อย่ากรอกข้อมูลไม่จริงเพื่อข้ามขั้นตอน |
| เปิดข้อมูลที่กรอกไว้หรือส่งไฟล์แล้วค้าง | ตรวจการเชื่อมต่ออินเทอร์เน็ตและรอสักครู่ก่อนลองใหม่ ตรวจว่าข้อมูลหรือไฟล์ถูกบันทึกแล้วหรือไม่ และตรวจรายการล่าสุดก่อนส่งไฟล์หรือชำระเงินซ้ำ |
| สร้างคิวอาร์โค้ดไม่ได้ หรือหมดเวลาจองห้อง | ตรวจยอดเงินที่ชำระไว้และสถานะห้องว่าง จากนั้นขอคิวอาร์โค้ดใหม่เมื่อระบบอนุญาต อย่าสันนิษฐานว่าคิวอาร์โค้ดเดิมถูกยกเลิกในแอปธนาคารแล้ว |
| ส่งหลักฐานการชำระแล้วไม่เห็นผล | ตรวจสถานะล่าสุด หากระบบยังตรวจสอบอยู่หรือต้องตรวจเพิ่มเติม ให้รอหรือติดต่อผู้ดูแลพร้อมเลขอ้างอิง |
| ระบบอ่านข้อความจากเอกสารผิด | ตรวจและแก้ข้อมูลในแบบฟอร์มโดยเทียบกับเอกสารต้นฉบับก่อนส่ง การอ่านข้อความอัตโนมัติเป็นเพียงตัวช่วย |
| ลงทะเบียนใบหน้าไม่ครบ | ทำตามข้อความแนะนำบนหน้าจอและส่งข้อมูลต่อเมื่อระบบแจ้งให้ทำ ตรวจสอบผลการบันทึกจากสถานะในระบบ เพราะภาพที่แสดงบนหน้าเว็บไม่ได้ยืนยันว่าบริการภายนอกบันทึกครบแล้ว |
| ไม่ได้รับรหัสยืนยันหรือการแจ้งเตือน | ตรวจสอบหมายเลขโทรศัพท์และการเชื่อมต่อ แล้วติดต่อผู้ดูแลระบบ การส่งข้อความจริงขึ้นอยู่กับการตั้งค่าบริการที่ระบบใช้งาน |
| สถานะงานซ่อมหรือผู้มาติดต่อไม่ตรงที่คาด | ตรวจสอบสถานะล่าสุดและสิทธิ์การใช้งาน แล้วติดต่อผู้ดูแลพร้อมเลขอ้างอิง หลีกเลี่ยงการกดส่งซ้ำหลายครั้ง |

เมื่อติดต่อผู้ดูแล ให้แจ้งวันและเวลาโดยประมาณ หน้าที่ใช้งาน เลขอ้างอิงรายการ (ถ้ามี) และข้อความที่ระบบแสดง ห้ามส่งรหัสผ่าน รหัสยืนยัน OTP คุกกี้หรือโทเคน เลขบัตรประชาชนเต็ม หรือข้อมูลการชำระเงินผ่านช่องทางสาธารณะ

## ข.7 ข้อจำกัดของระบบ

ระบบต้นแบบทำงานผ่านเว็บและเชื่อมต่อบริการภายนอกในบางขั้นตอน เช่น การอ่านข้อความจากเอกสาร การตรวจสอบใบหน้า การชำระเงิน และการส่งรหัสยืนยันหรือการแจ้งเตือน ผลการใช้งานจึงขึ้นอยู่กับความพร้อมและการตั้งค่าของบริการเหล่านั้น หากบริการไม่พร้อม ระบบอาจทำรายการไม่สำเร็จหรือแสดงผลล่าช้า ผู้ใช้ควรตรวจสถานะล่าสุดและทำตามคำแนะนำบนหน้าจอ

โครงงานยังไม่ได้ยืนยันการทำงานร่วมกับกล้องวงจรปิดหรืออุปกรณ์ควบคุมประตูจริง การบันทึกหรือแสดงข้อมูลผู้มาติดต่อในระบบจึงไม่ใช่หลักฐานว่ามีการเปิดประตูจริง และผลการอ่านข้อความหรือการตรวจใบหน้าไม่ใช่การรับรองความถูกต้องในทุกกรณี

## ข.8 ข้อควรระวังในการเก็บภาพและข้อมูล

- ใช้ข้อมูลทดสอบที่แยกจากข้อมูลจริง และหลีกเลี่ยงการใช้บัตรประชาชน ใบหน้า ลายเซ็น ที่อยู่ เบอร์โทร เลขบัญชี หรือหลักฐานการชำระเงินจริงเป็นภาพประกอบ
- หากจำเป็นต้องใช้ภาพจากระบบ ให้ปกปิดข้อมูลส่วนบุคคลและข้อมูลทางการเงินก่อนเผยแพร่ รวมถึงตรวจแถบชื่อไฟล์และข้อความแจ้งเตือนว่าไม่มีข้อมูลหลุดออกมา
- ห้ามแสดงรหัสผ่าน รหัสยืนยัน OTP คุกกี้หรือโทเคน รหัสรับชำระเงินจริง หรือค่าตั้งค่าลับในภาพและคู่มือ
- ก่อนจับภาพ ให้ปิดแถบเครื่องมือสำหรับนักพัฒนาเว็บและแถบเครือข่ายที่อาจแสดงข้อมูลคำขอหรือข้อมูลลับ
- สถานะในภาพยืนยันเฉพาะสิ่งที่ปรากฏบนหน้าจอ ณ เวลาที่จับภาพ ควรระบุวันทดสอบและสภาพแวดล้อมเมื่อนำภาพไปใช้อ้างอิงผล

## ข.9 การดูแลข้อมูลส่วนบุคคล

- อ่านคำชี้แจงและตรวจสอบวัตถุประสงค์ก่อนให้ความยินยอม การยินยอมให้ใช้ข้อมูลเพื่อสมัครเข้าพักและการลงทะเบียนใบหน้าเป็นคนละขั้นตอน
- กรอกข้อมูลให้ตรงกับเอกสารของตน ตรวจทานก่อนส่ง และแนบเฉพาะเอกสารหรือภาพที่ระบบร้องขอ
- ใช้บัญชีของตนเอง ออกจากระบบเมื่อใช้อุปกรณ์สาธารณะ และไม่เปิดเผยรหัสผ่านหรือรหัสยืนยันแก่ผู้อื่น
- หลีกเลี่ยงการส่งเลขบัตรประชาชนเต็ม ที่อยู่ เบอร์โทร ภาพใบหน้า หลักฐานการชำระเงิน หรือข้อมูลบัญชีผ่านช่องทางสาธารณะ หากต้องติดต่อผู้ดูแลให้ใช้ช่องทางที่หอพักกำหนด
- หากพบว่าข้อมูลของตนไม่ถูกต้องหรือมีข้อกังวลเกี่ยวกับข้อมูลที่ส่ง ให้ติดต่อผู้ดูแลระบบเพื่อขอคำแนะนำ และไม่แก้ไขข้อมูลของบัญชีผู้อื่น

## ข.10 แนวทางเมื่อเกิดข้อผิดพลาด

1. หยุดกดส่งหรือชำระรายการเดิมซ้ำ โดยเฉพาะเมื่อเป็นการสมัคร ส่งเอกสาร ส่งหลักฐานการชำระ หรือส่งคำขอที่อาจสร้างรายการใหม่
2. อ่านข้อความบนหน้าจอและจดวันเวลาโดยประมาณ หน้าที่เกิดปัญหา ขั้นตอนที่ทำก่อนพบปัญหา และเลขอ้างอิงรายการ (ถ้ามี)
3. กลับไปตรวจรายการหรือสถานะล่าสุดในระบบก่อนลองอีกครั้ง หากรายการยังอยู่ระหว่างตรวจสอบ ให้รอตามคำแนะนำหรือสอบถามผู้ดูแล
4. หากต้องส่งภาพหน้าจอเพื่อให้ตรวจสอบ ให้ปิดข้อมูลส่วนบุคคลและข้อมูลทางการเงินก่อน และอย่าส่งรหัสผ่าน รหัสยืนยัน หรือข้อมูลเข้าสู่ระบบ
5. ติดต่อผู้ดูแลพร้อมรายละเอียดข้างต้น หากปัญหาเกี่ยวกับยอดเงิน การคืนเงิน หรือสถานะที่ไม่ตรงกับหลักฐาน ให้แนบเฉพาะหลักฐานที่จำเป็นผ่านช่องทางที่ผู้ดูแลกำหนด
