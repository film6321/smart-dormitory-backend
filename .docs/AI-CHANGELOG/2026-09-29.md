# AI Change Log — 2026-09-29

## Visitor reception flow and Monitor door simulation

- Required PDPA consent, a verified OCR result, required identity/address fields, an existing room, and the assigned resident name for visitor registration.
- Added expiry handling and protected visitor record access.
- Implemented an in-app door simulation for authenticated Admin users; it does not call physical hardware.
- `unlock` writes a `MONITOR_DOOR` audit event, publishes it to the existing scan-history SSE feed, and schedules automatic `lock` after five seconds. A manual lock cancels that scheduled close and records its own event.
- Door events persist in `AccessLog`, reload through `/scan-history`, do not change Visitor status, and do not affect biometric check-in/check-out totals.
- Updated the API contract to describe the simulation and its limits.
