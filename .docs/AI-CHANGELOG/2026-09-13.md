# Changelog 2026-09-13

## สิ่งที่ทำเสร็จ

- **[database/core]** กำหนด `DbClient` type (`PrismaClient | Prisma.TransactionClient`) ใน `src/database/db.ts` เพื่อรองรับ Transaction/Prisma client injection แบบ type-safe ไม่ต้องพึ่งพา `any`
- **[tenants]** Refactor `TenantsRepository`, `TenantsService`, และ `TenantsController`
  - ใช้ `Prisma.TenantCreateInput`, `Prisma.TenantUpdateInput`, `Prisma.TenantWhereInput`
  - แก้ไข `req as AuthenticatedRequest` สำหรับการอ่าน `req.user`
  - ปรับปรุง dependency injection ให้รับ `DbClient`
- **[users]** Refactor `UsersRepository`, `UsersService`, และ `UsersController`
  - กำจัด `any` casts ใน transaction และ query methods ทั้งหมด
  - ใช้ `Prisma.UserCreateInput`, `Prisma.UserUpdateInput`, `Prisma.UserWhereInput` และ `DbClient`
- **[rooms]** Refactor `RoomsRepository`, `RoomsService`, และ `RoomsController`
  - รองรับ `DbClient` และจัดการ typed Prisma relations
- **[visitor]** Refactor `VisitorRepository` และ `VisitorService`
  - ใช้ `Prisma.VisitorCreateInput` และ `Prisma.VisitorUpdateInput`
- **[billing]** Refactor `PaymentBatchService`, `BillingRepository`, และ `BillingService`
  - ปรับปรุง `toBatchResponse` เป็น null-safe response mapping
  - จัดการ types ของ Prisma nested queries/transactions อย่างสมบูรณ์
- **[ocr]** Refactor `OcrService`
  - กำจัด `any` casts ในการสร้างและอัปเดต OCR documents
  - แก้ไข Prisma relation connect syntax ให้ตรงตาม Schema contract
- **[face-verification]** Refactor `FaceVerificationService`
  - กำจัด `any` casts และผูก type `CameraScanSnapshot` เข้ากับ live stream processing
- **[notifications]** Refactor `NotificationController`, `NotificationService`, และ `notificationWorker`
  - เปลี่ยน `req as any` เป็น `AuthenticatedRequest`
  - ลบ unused imports และ clean up types
  - รองรับ `DbClient` ใน background worker processes
- **[performance & concurrency]** 
  - แก้ไข Race Condition Error Handling: ดักจับ Prisma Error code `P2002` ใน `AuthService.register` ให้ส่ง `HTTP 400 ('อีเมลหรือชื่อผู้ใช้นี้ถูกใช้งานแล้ว')` แทน `HTTP 500`
  - เพิ่ม `UV_THREADPOOL_SIZE: 64` ใน Docker environment เพื่อปลดล็อก Libuv Threadpool สำหรับ Bcrypt hashing
  - เปิด Multi-worker Backend 2 Replicas หลัง Nginx Load Balancer เพิ่ม Throughput จาก ~109 req/s เป็น **344.95 req/s (เพิ่มขึ้น 315%)** และลด Latency P95 ลงเหลือ 282ms
