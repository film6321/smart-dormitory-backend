# Changelog 2026-07-07

## ✅ สิ่งที่ทำเสร็จ

- [tests] เพิ่ม unit test ใหม่ `tests/unit/route-aliases-additional.test.ts` เพื่อครอบคลุม alias route ของ OCR และ billing อีกชุดหนึ่ง
- [ocr] ยืนยันว่า `POST /verify`, `POST /verify-id-card`, `POST /verify-id-card/jobs`, และ `GET /jobs/:jobId` ถูกลงทะเบียนแล้ว
- [billing] ยืนยันว่า alias route `POST /:id/upload` ทำงานคู่กับ `POST /:id/upload-slip`
- [shared] ปรับปรุง `src/shared/rate-limit-store.ts` ให้ใช้ `MemoryStore` ในโหมดทดสอบหรือเมื่อปิด Redis rate limit เพื่อให้ `npm test` ไม่พึ่ง Redis host จริง
- [tests] อัปเดต `tests/run-tests.cjs` เพื่อกำหนด `NODE_ENV=test` และ `DISABLE_REDIS_RATE_LIMITS=true` ขณะรันชุดทดสอบ
- [docs] ปรับ `SYSTEM-BLOCK-DIAGRAM.md` ให้ระบุว่า Redis rate limiting เป็น optional / integration dependency
- [verification] รัน `npm test` สำเร็จทั้งหมด `23` tests / `0` failures
- [face-verification] สร้างโมดูล `src/modules/face-verification/` (routes, controller, service, types) เพื่อดึงและประมวลผล Face Register & Verify ร่วมกับ Python FastAPI service
- [tests] พัฒนา `tests/unit/face-verification.test.ts` โดยใช้ Mock fetch เพื่อทดสอบการสตรีมภาพ/เชื่อมต่อระบบ และทำการ Register ใน `run-tests.cjs` (ผ่านสำเร็จ)
- [env] เพิ่ม config `FACE_API_URL` และ `FACE_API_KEY` เข้าสู่ `.env` สำหรับเชื่อมต่อไปยังเครื่องปลายทาง

## 🔧 ปัญหาที่แก้ไข

- แก้ปัญหาทดสอบไม่สามารถรันได้ในสภาพแวดล้อมที่ไม่มี Redis ด้วยการ fallback เป็น in-memory rate limiter เฉพาะใน test mode
- ปรับ diagram ให้ชัดเจนขึ้นว่า Redis เป็น dependency สำหรับฟีเจอร์ integration เท่านั้น ไม่ใช่ requirement จำเป็นสำหรับการรัน backend ในระดับ unit test
- แก้ไขปัญหา Type Compatibility (`Buffer` to `BlobPart`) ในโมเดลของ Global Blob เอนจินโดยการแปลงค่าให้ผ่านครอบด้วย `Uint8Array` ใน API Service
